# Nothing matches Claude Harness for Copilot yet

No VS Code extension, first-party or third-party, does for GitHub Copilot what Claude Harness does for Claude Code. VS Code itself comes closest. Since March 2026 its built-in **Agent Customizations editor** lists and edits Copilot's agents, skills, instructions, prompt files, hooks, MCP servers and plugins in user and workspace scope, and its **Agent Debug Logs** panel shows one session's tool calls, tokens, subagents and a flow chart. Both are labelled Preview. Outside VS Code the field is wide and shallow: well over 100 third-party extensions touch Copilot's customization files and well over 100 more track Copilot usage, but each covers one slice, almost all have under 2,000 installs and a single maintainer, and the ones that call themselves a "harness" have under 125 installs each. Getting close to Claude Harness's breadth today takes at least three extensions on top of VS Code's built-ins, and **six Claude Harness features exist nowhere for Copilot**: lists of what never ran across sessions, the concurrency and scatter views, findings, one table of every repository, Plugin Hunter and Automation Hunter. Claude Harness itself has **52 installs** ([Marketplace](https://marketplace.visualstudio.com/items?itemName=integrations-at.claude-harness)), so "this quality" means depth of features, not adoption: by install count it sits among its nearest Copilot counterparts. There is room for a Copilot equivalent in the cross-session, cross-repository and hygiene features. The data is harder to get, though: Copilot's detailed logs have to be switched on before a session runs, and the sources disagree on how complete its local credit and token records are.

## VS Code already ships the editor and the single-session debugger

Microsoft has built the "edit everything in one place" half of Claude Harness into VS Code, for free. The **Agent Customizations editor**, introduced in **VS Code 1.113 on March 25, 2026** as the "Chat Customizations editor", "provides a central place to discover, create, and manage customizations for the selected harness". Depending on the item it shows configuration forms, an inline editor with syntax highlighting and validation, or read-only details. It covers User and Workspace scope and works with each agent harness VS Code runs: Copilot, Local, Claude and Codex ([VS Code docs](https://code.visualstudio.com/docs/agent-customization/overview); [1.113 release notes](https://code.visualstudio.com/updates/v1_113)). Later releases turned on plugins and MCP servers globally or per workspace (1.112), made a marketplace **Browse** page the editor's home, and added completions, hovers and validation for `model`, `tools`, `skills`, hooks and agent-scoped MCP servers in custom agent files (1.144, October 28, 2026), along with `/plugin`, `/mcp` and `/skills` chat commands ([1.112](https://code.visualstudio.com/updates/v1_112); [1.144](https://code.visualstudio.com/updates/v1_144)). A **Migrations** page flags customizations that sit in the wrong place or format, and a Marketplace skill with missing files gets **Repair** ([overview](https://code.visualstudio.com/docs/agent-customization/overview)). The editor only sees the open workspace: there is no view across repositories, and looking up parent folders in a monorepo is a setting that is off by default.

On the session side, VS Code is in places deeper than Claude Harness. The **Agent Debug Logs** panel (Preview since 1.110, with past sessions kept since 1.116 on April 15, 2026) has a Logs view that can be grouped by subagent. It also has a Summary of tool calls, token usage, errors and duration, an **Agent Flow Chart** that "visualizes the sequence of interactions between agents and subagents", and a **Cache Explorer** that marks where consecutive model requests first diverge. Discovery events show whether each customization was loaded, skipped or rejected ([Debug chat interactions](https://code.visualstudio.com/docs/agents/agent-troubleshooting/chat-debug-view)). Chat itself shows the **cost of the whole session** (1.126, June 24, 2026), the **AI credits each subagent used** (1.127, July 1, 2026) and input, cached and output tokens per model for each turn (1.135, August 26, 2026) ([1.126](https://code.visualstudio.com/updates/v1_126); [1.127](https://code.visualstudio.com/updates/v1_127); [1.135](https://code.visualstudio.com/updates/v1_135)). Checkpoints, available since 1.103, roll back files and chat history together ([1.103](https://code.visualstudio.com/updates/v1_103)). OpenTelemetry tracing since 1.119 records agent, tool and hook spans with cache token breakdowns ([1.119](https://code.visualstudio.com/updates/v1_119)).

The gaps are in how these features work. **Capture is not retroactive**: the logs need experimental settings switched on before a session ([chat-debug-view](https://code.visualstudio.com/docs/agents/agent-troubleshooting/chat-debug-view)), whereas Claude Harness reads transcripts Claude Code has already written. VS Code reports cost in Copilot AI credits, not dollars per token class. Restoring a checkpoint rolls everything back and deletes the later turns, with no card listing the files first ([Review code edits](https://github.com/microsoft/vscode-docs/blob/main/docs/agents/run/review-code-edits.md)). Microsoft's experimental **Session timeline** plugin draws only the live session and adds nothing up across sessions ([vscode-team-kit](https://github.com/microsoft/vscode-team-kit/tree/main/session-timeline)). Two first-party extensions add a quality layer. **Chat Customizations Evaluations** checks customization files for ambiguity and contradictions; it has **1,006,321 installs but a 2.08 rating from 26 reviews** ([Marketplace](https://marketplace.visualstudio.com/items?itemName=ms-vscode.vscode-chat-customizations-evaluations)). **GitHub Copilot Evals (Preview)**, published November 3, 2026, promises to "inspect GitHub Copilot customizations and run evals from one VS Code pane" ([Marketplace](https://marketplace.visualstudio.com/items?itemName=GitHub.copilot-evals)). VS Code has also read `CLAUDE.md`, `.claude/rules`, `.claude/agents`, `.claude/skills` and Claude hooks since 1.109 ([1.109](https://code.visualstudio.com/updates/v1_109)), so the built-in editor already partly edits Claude Code harnesses as well as Copilot ones.

## Third-party managers split the harness into one-pillar tools

A Marketplace search on November 4, 2026 returned 1,310 hits, of which about 170 are relevant. Installs go to catalogs and installers, not to editing or hygiene. The one six-figure extension, **Copilot MCP + Agent Skills Manager (about 112,000 installs)**, only searches for and installs MCP servers and skills. It collects anonymous usage data and steers users to the vendor's paid Cloud MCP service ([Marketplace](https://marketplace.visualstudio.com/items?itemName=AutomataLabs.copilot-mcp)). Tim Heuer's **Awesome Copilot (20,998 installs)** downloads files from awesome-copilot but has not been updated since March 2026 ([Marketplace](https://marketplace.visualstudio.com/items?itemName=TimHeuer.awesome-copilot)). Amadeus's **AI Primitives Hub** (4,165 installs plus 10,666 on Open VSX, 155 open issues) is the most enterprise-minded: team hubs, a validated deployment manifest, a CLI and a CI action ([Marketplace](https://marketplace.visualstudio.com/items?itemName=AmadeusITGroup.prompt-registry); [repo](https://github.com/AmadeusITGroup/ai-primitives-hub)). About half of the Copilot managers are stale by a six-month measure. Copilot's file formats keep changing (chat modes became agents, hooks moved to `.github/hooks/*.json`), and solo maintainers do not keep up.

Two small extensions come closest to "edit everything in one place". **Agent Resources Ninja (93 installs, 5.0 from 5 ratings, updated October 27, 2026)** covers the most Copilot kinds: skills, agents, prompts, instructions, hooks, MCP config and plugin manifests, across workspace, user profile and `~/.copilot`. It also warns when a hook points at a missing script ([Marketplace](https://marketplace.visualstudio.com/items?itemName=yamapan.agent-resources-ninja)). **Copilot Workspace Manager (52 installs, 0 stars, last updated June 2026)** is the only one that reads Copilot CLI's configuration and plugin state. It checks which `applyTo` instructions apply to the active file and lists CLI session history from `events.jsonl` ([Marketplace](https://marketplace.visualstudio.com/items?itemName=Knworks.copilot-workspace-manager); [repo](https://github.com/Knworks/copilot-workspace-manager)). Neither has been confirmed to write frontmatter through form fields, and **no third-party extension offers typed frontmatter fields or a tool picker for Copilot**. Typing help exists only as language-server completions.

The "keep it lean" checks are spread across separate small extensions. **agnix** is the most mature linter, with 757 rules, auto-fix, a language server and 467 GitHub stars. It has **35 rules for Copilot against 170 for Claude Code**, and its VS Code extension has about 270 installs ([repo](https://github.com/agent-sh/agnix); [Marketplace](https://marketplace.visualstudio.com/items?itemName=avifenesh.agnix)). Nifty Agent Config flags broken links, size limits and duplicate or conflicting instructions across files ([Marketplace](https://marketplace.visualstudio.com/items?itemName=nifty.nifty-agent-config)). SkillMap-Solo, first released November 3, 2026, sets token budgets per skill, catches drift between a skill and its copies, and estimates what Copilot would load for a file ([Marketplace](https://marketplace.visualstudio.com/items?itemName=masanori-satake.skillmap-solo)). ContextGuard keeps duplicate detection in its paid tier ([Marketplace](https://marketplace.visualstudio.com/items?itemName=bearinblue.contextguard)). All of them detect duplicate copies, but **none can retire a copy** between global and repository scope. The extensions with "harness" in their name are early-stage: Harness Dashboard has 115 installs and reads only `.github/copilot-instructions.md` on the Copilot side ([repo](https://github.com/marcmassa/harness-manager)), Harness Manager has 122 ([Marketplace](https://marketplace.visualstudio.com/items?itemName=AdmiralGallade.harness-manager)) and Harness Lens has 21 ([Marketplace](https://marketplace.visualstudio.com/items?itemName=harness-lens.harness-lens)). The cross-agent tools with real adoption are command-line programs with no VS Code interface: **rulesync (323,487 npm downloads a week)** generates Copilot rules, MCP, commands, subagents, skills, hooks and permissions ([repo](https://github.com/dyoshikawa/rulesync)), **Microsoft's APM (4,192 stars)** packages and installs every Copilot customization kind, plugins included ([repo](https://github.com/microsoft/apm)), and `npx skills` sees **5.5 million downloads a week** ([repo](https://github.com/vercel-labs/skills)). They generate and install files. None of them reads session data.

## Copilot session analytics stop at cost and quota meters

Copilot keeps its session data in four local stores, and each has gaps. VS Code chat sessions are JSONL files under `workspaceStorage/*/chatSessions/`. Copilot Chat debug logs record per-call tokens and credits but are opt-in ([LedgerLM](https://github.com/tatsat3mutee/ledgerlm); [Copilot Cost Analyzer](https://marketplace.visualstudio.com/items?itemName=SathvikCheela.copilot-cost-analyzer)). An OpenTelemetry trace database, also opt-in, by default **stores prompts, responses and tool results in plain text** ([Token Pie](https://marketplace.visualstudio.com/items?itemName=token-pie.token-pie)). Copilot CLI writes `~/.copilot/session-state/<id>/events.jsonl`, with event types such as `subagent.started`, `skill.invoked` and `tool.execution_complete`, and keeps file backups for rewind ([events.jsonl reference](https://gist.github.com/RockNoggin/8cc87f640ce5e3d284298a6db21f7523); [CLI Timeline](https://marketplace.visualstudio.com/items?itemName=ayushagg31.cli-timeline)). Copilot **deletes logs after about 14 days** ([GridWatch](https://github.com/abuxton/gridwatch)), and the cloud coding agent leaves nothing on the PC. So the raw material for a delegation map exists, but every tool has to make the user switch logging on first and has to snapshot data before it disappears.

Of well over 100 usage extensions, only five pass 7,000 installs, and none of them analyzes how agents ran. **AI Engineering Fluency (16,321 installs, 123 stars, updated November 3, 2026)** is the best-maintained Copilot tracker, but it measures usage habits and tokens, not how a session's agents ran ([Marketplace](https://marketplace.visualstudio.com/items?itemName=RobBos.ai-engineering-fluency)). SpecStory (about 25,000 installs plus 99,463 on Open VSX) saves and searches chat history but shows no token or agent analytics ([Marketplace](https://marketplace.visualstudio.com/items?itemName=SpecStory.specstory-vscode)). agsoft's Claude Code and Codex Assist (11,797 installs) adds per-turn diffs with undo for Copilot CLI and VS Code chat ([Marketplace](https://marketplace.visualstudio.com/items?itemName=agsoft.claude-history-viewer)). The deepest session views come from tiny extensions. **Copilot Cost Tracker (896 installs)** has a Turn Explorer of LLM and tool calls per turn with cache percentage, cost per model, and a switch between chat and CLI ([Marketplace](https://marketplace.visualstudio.com/items?itemName=Hoxlegion.copilot-cost-tracker)). Copilot Live Cost & Token Tracker (147 installs) breaks each prompt into model calls, tool calls and subagent activity with their cost ([Marketplace](https://marketplace.visualstudio.com/items?itemName=ervi.copilot-live-cost-tracker)). Copilot CLI Chat's **Sub-Agent Dock** (3,965 installs) gives each subagent a card showing its model, tool calls, tokens and duration ([repo](https://github.com/darthmolen/vscode-extension-copilot-cli)).

No tool lists **which customizations never ran**. Copilot Usage Studio (39 installs) comes nearest. It shows "when customization text appears in visible VS Code request logs" and does not claim to prove more, and it does not support Copilot CLI ([Marketplace](https://marketplace.visualstudio.com/items?itemName=fortunes-guardian.copilot-usage-studio-vscode)). LedgerLM counts subagent runs, tool calls, skill invocations and hook runs, but the notes could not confirm that this works for Copilot as well as for Claude Code ([LedgerLM](https://github.com/tatsat3mutee/ledgerlm)). The signals exist in CLI events and VS Code debug logs. No tool matches them against the customization files on disk.

## Six Claude Harness features exist nowhere for Copilot

The table compares each Claude Harness feature ([README](https://marketplace.visualstudio.com/items?itemName=integrations-at.claude-harness)) with the best Copilot equivalent the research found, built-in or third-party.

| Claude Harness feature | Best Copilot equivalent | Status |
|---|---|---|
| All kinds in one tree, global and per repository | Built-in Agent Customizations editor; Agent Resources Ninja; Copilot Workspace Manager | Present, open workspace only |
| Frontmatter as typed fields, tool picker | Built-in forms for some kinds and agent-file validation (1.144); agnix and Nifty completions | Partial |
| Session cost, tokens, tool calls | Agent Debug Logs Summary, session cost, credits per subagent; Copilot Cost Tracker | Present, logging must be on |
| Delegation map with hook-denied calls | Agent Flow Chart (hook display undocumented); Sub-Agent Dock | Partial |
| Concurrency and scatter views | None found | **Missing** |
| Findings: failed or silent agents, failing hooks | None found | **Missing** |
| Checkpoints with per-file diff and restore | Built-in Restore Checkpoint (rolls back everything); agsoft diff and undo; CLI Timeline (stale) | Partial |
| Find what never runs, across sessions | Copilot Usage Studio (shows "used" only); Discovery events per session | **Missing** |
| Size, duplicate and dead-pointer checks | SkillMap-Solo, Nifty, ContextGuard, agnix, each separate; no retire action | Partial |
| Effective harness of a session | Discovery events; `applyTo` check for the active file (Copilot Workspace Manager) | Partial |
| Every repository in one table, bulk-edit guard | None found | **Missing** |
| Plugin Hunter | None for Copilot (SkillJetty builds Claude bundles only) | **Missing** |
| Automation Hunter | None found | **Missing** |
| Drawings per element | ForgeOne Flow workspace map; Agent Flow Chart for one session | Partial |
| Handover from other apps | Built-in continuation of outside Copilot or Claude sessions (1.135) | Partial |
| Plugin version check and update | Built-in auto-update and `/plugin update` | Present |
| Command line, scripts, mentions | APM, rulesync, agnix CLIs; `@mcp` chat participant | Partial |

Sources for the rows not cited above: [SkillJetty](https://marketplace.visualstudio.com/items?itemName=DavidFarris.skill-builder), [ForgeOne Flow](https://marketplace.visualstudio.com/items?itemName=anghelll.forgeone-flow). What separates Claude Harness is not any single row but that every row lives in one product and reads one data source. On the Copilot side, the "Present" and "Partial" rows come from about eight different extensions plus the built-ins. Every "Missing" row needs session data matched against an inventory across repositories, and nobody has built that.

## The sources disagree on six data facts

| Fact | One source says | Another source says |
|---|---|---|
| Does ccusage read Copilot? | No Copilot support found in the README ([GitHub](https://github.com/ccusage/ccusage)) | `ccusage copilot` (Beta) reads Copilot CLI session-state and OTel files ([ccusage guide](https://ccusage.com/guide/copilot/)) |
| Does waterplane track Copilot usage? | Counts Copilot plan and premium requests locally, Copilot Chat token use, optional quota call | Sessions, costs and context window are Claude Code only; Copilot CLI not seen. Both read the same [Marketplace page](https://marketplace.visualstudio.com/items?itemName=waterplane-dev.waterplane) |
| Are Copilot hook runs logged? | No hook events documented in chat sessions, debug logs or `events.jsonl` ([reference](https://gist.github.com/RockNoggin/8cc87f640ce5e3d284298a6db21f7523)) | VS Code OTel traces have `execute_hook` spans for Local, Copilot CLI and Claude sessions ([1.119](https://code.visualstudio.com/updates/v1_119)); LedgerLM claims hook timings ([LedgerLM](https://github.com/tatsat3mutee/ledgerlm)) |
| Do chat sessions record credits? | Each turn records `copilotCredits` ([Happy AI](https://marketplace.visualstudio.com/items?itemName=happymates.happy-ai)) | Chat panel records no credits locally ([GHCP Insights Dashboard](https://marketplace.visualstudio.com/items?itemName=ShubhJ.ghcp-dashboard)); chat sessions showed 6.15 of 13.6 credits, about 55% short ([Token Pie](https://marketplace.visualstudio.com/items?itemName=token-pie.token-pie)) |
| Are cached tokens recorded? | No, VS Code does not log them ([Copilot Tokens](https://marketplace.visualstudio.com/items?itemName=yuyuanjingxuan.copilot-tokens)) | Debug logs carry `cachedTokens` ([LedgerLM](https://github.com/tatsat3mutee/ledgerlm)); OTel includes cache read and creation ([1.119](https://code.visualstudio.com/updates/v1_119)) |
| Are CLI shutdown totals cumulative? | Cumulative per session and model ([ccusage guide](https://ccusage.com/guide/copilot/)) | Not cumulative ([cli-tools issue](https://github.com/microsasa/cli-tools/issues/2)) |

Some of these can be settled from the evidence, others cannot. On ccusage, the guide page is more specific than a README scan, so Copilot CLI support most likely exists as a beta, but the two sources disagree. On waterplane, both notes read the same listing and agree only that it prices Copilot instruction files per request, so its Copilot usage tracking is unresolved. Hook logging is probably both true: VS Code's own opt-in traces include hook spans, while the file formats third-party tools parse do not document them. On credits, Token Pie checked its figures against the drop in the quota, which is the strongest evidence, so the chat-session files are best treated as undercounting agent-mode work. The cached-token and cumulative-total conflicts probably reflect different Copilot versions, and neither is settled. Install counts also differ slightly between pulls on the same day (Claude Harness 52 or 53, agnix 270 or 271). That does not change any conclusion.

## Conclusion

The real competitor for a Copilot Claude Harness is Microsoft, not the long tail of extensions. VS Code ships a new release every week and has already absorbed the editor, the per-session debugger and plugin updates into core. It reads `.claude/` files and runs a Claude harness, so its editor is starting to compete with Claude Harness on Claude Code too, not only on Copilot. What VS Code and every third-party tool still lack is the analysis that matches all sessions against all customization files across all repositories: never-used lists, findings, concurrency, duplicates retired across scopes, plugins proposed from your own skills. That is where Claude Harness's value lies, and it is also the hardest part for Microsoft to ship as a per-workspace Preview feature.

A Copilot version cannot simply copy Claude Harness's promise that it reads what is already written, with no hook, proxy or server. On Copilot, accurate per-call data needs debug logging or OpenTelemetry switched on in advance. The trace database stores prompts in plain text. Logs disappear after about 14 days, and cloud agent sessions leave nothing on the PC. Any credible Copilot version would therefore need a setup check that shows which data source is active, its own snapshots, and a reconciliation against the quota. That is a different product shape, not just a port. All third-party feature claims here come from READMEs and Marketplace listings; no extension was installed or tested.
