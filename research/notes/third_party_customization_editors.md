# Third-party VS Code extensions that manage the GitHub Copilot customization layer (as of 2026-11-04)

Method note: install counts, ratings, versions and last-update dates were pulled on 2026-11-04 from the public Visual Studio Marketplace gallery API (`_apis/public/gallery/extensionquery`, 36 search terms, 1,310 unique hits, filtered by hand to ~170 relevant), Open VSX search API (16 terms), and `gh api repos/<owner>/<repo>` for stars, open issues and last push. READMEs and `package.json` contributions were read from the Marketplace asset store. Each Marketplace item URL below is `https://marketplace.visualstudio.com/items?itemName=<id>`. "Stale" means no Marketplace update since 2026-05-04 (6+ months).

## Q1. Which extensions exist, and what does each cover?

### Takeaway
The field is large (well over 100 extensions touch Copilot instructions, prompts, agents, skills, hooks, MCP or plugins) but shallow: almost every extension is either a catalog/installer (Awesome Copilot browsers, skill managers, MCP installers) or a single-purpose linter. Only one, AutomataLabs "Copilot MCP + Agent Skills Manager", has six-figure installs; nearly everything else sits under 2,000 installs, with 0 to 50 GitHub stars, built by one maintainer.

### Customization kinds to cover (baseline)
- VS Code's customization docs list custom instructions, prompt files, agent skills, custom agents, hooks, agent plugins (from plugin marketplaces) and MCP servers; `/create-instruction`, `/create-prompt`, `/create-skill`, `/create-agent`, `/create-hook` scaffold files; `chat.customizations.marketplace.enabled` is on by default; discovery is limited to open workspace folders unless `chat.useCustomizationsInParentRepositories` is set. Source: [VS Code: Customize AI](https://code.visualstudio.com/docs/agent-customization/overview), [VS Code: customization concepts](https://code.visualstudio.com/docs/copilot/concepts/customization)
- Built in (noted only in passing): the "Agent Customizations" editor (`Chat: Open Customizations`) discovers, creates and manages prompt files; skill folders checked by default include `.agents/skills`, `.github/skills`, `.claude/skills` and their user-home equivalents. Source: [VS Code: prompt files](https://code.visualstudio.com/docs/agent-customization/prompt-files)

### Inferences
- Install volume concentrates on catalog/installer UX (browse and drop files into `.github/`), not on editing or hygiene. Linters are newer (most first published 2026) and have tiny install bases; agnix is the only linter with real community traction (467 stars).
- About half of the Copilot-relevant managers are already stale against the 6-month bar (TimHeuer's two, Copilot ToolBox, Awesome Coding Assistants, Promptitude, ContextShare, AgentLint, gardltio), which signals a fast-moving file format (chat modes renamed to agents, hooks moved to `.github/hooks/*.json`) that small maintainers do not keep up with.
- Copilot CLI's `~/.copilot` tree is supported only by a handful (Copilot Workspace Manager, Agent Resources Ninja, Agent Skills Ninja, SkillBridge, Twinport, Agent Pack Installer, Skill Manager for Copilot, Agent Plugins Browser).

### Gaps
- Open VSX: only extensions returned by 16 searches were checked; absence from my Open VSX list does not prove absence from Open VSX.
- Ratings for `AmadeusITGroup.prompt-registry` were not captured. Marketplace ratings for most items have 0 to 8 reviews, too few to compare quality.
- Repos for Skill Manager for Copilot, Copilot Skill & Instruction Viewer, ForgeOne Flow and Smart MCP Manager return 404 (private or deleted); their stars and commit cadence are unknown.
- I did not install or run any extension; feature claims come from READMEs and package manifests only.

## Q2. Per-extension feature matrix: frontmatter as typed fields, duplicate / oversized / broken-reference detection, hooks, MCP, plugins

### Takeaway
No third-party extension found edits Copilot frontmatter through typed form fields or offers a tool picker. Typed help exists only as LSP completions and diagnostics (agnix, Nifty) or read-only inspection (Copilot Workspace Manager). Hygiene features (oversize, duplicates, dead references, drift between copies) exist, but each lives in a different small extension. Hooks are covered by three (Hook Studio, Agent Resources Ninja, Copilot Workspace Manager, plus agnix for validation); plugins by three (Agent Plugins Browser, Agent Resources Ninja, Copilot Workspace Manager).

- A user who wants Claude-Harness-level coverage for Copilot today would need at least three extensions: one manager (Agent Resources Ninja or Copilot Workspace Manager), one linter (agnix or Nifty), one token/size view (SkillMap-Solo or ContextGuard).

## Q3. Which comes closest to Claude Harness's "edit everything in one place" and "keep the harness lean", and what is missing?

### Takeaway
For "everything in one place", the closest are Agent Resources Ninja (widest Copilot kind coverage across workspace, user profile and `~/.copilot`, actively maintained, but 93 installs) and Copilot Workspace Manager (the only one that reads Copilot CLI config, plugin state and evaluates which instructions apply, but 52 installs, 0 stars, last update June 2026). For "keep it lean", Nifty Agent Config and SkillMap-Solo come closest, with agnix the most mature validator. No single extension combines both halves, and none has meaningful adoption.

### Cited Findings
- Agent Resources Ninja: "managing skills, agents, prompts, instructions, hooks, and related AI coding resources" in three views (Workspace, User / Global Resource Home, Remote); kinds include "skills, agents, prompts, instructions, hooks, MCP config resources, plugin manifests, and Cursor rules"; install targets Workspace, User Profile, Global Resource Home or Custom; 93 installs, 5.0 from 5 ratings, v0.2.69 on 2026-10-27. [Marketplace](https://marketplace.visualstudio.com/items?itemName=yamapan.agent-resources-ninja), [repo](https://github.com/aktsmm/vscode-agent-resources-ninja)

[Marketplace](https://marketplace.visualstudio.com/items?itemName=Knworks.copilot-workspace-manager)

No telemetry."; Marketplace 1 install vs 1,048 on Open VSX. ### Mapping against Claude Harness features (missing = no extension found that does it for Copilot)
- One tree for all kinds, global + repo: partial (Agent Resources Ninja, Copilot Workspace Manager).
- Typed frontmatter editing + tool picker: missing (completions/diagnostics only: agnix, Nifty).
- Oversized skill detection: present but separate (SkillMap-Solo, ContextGuard, Nifty).
- Retire duplicate copies between global and repo: missing as an action; detection only (SkillMap-Solo drift, Nifty duplicates, Agent Skills Ninja install collisions).
- Dead pointers in instruction files: present but separate (Nifty, ForgeOne Flow, reflint, AgentLint).
- Effective harness a session loads: partial (Copilot Workspace Manager `applyTo` per active file, SkillMap-Solo load simulation, Skill & Instruction Viewer "always loaded" chips); none reconstructs it from an actual session.
- Plugin version check and sync: partial (Agent Plugins Browser install/update, stale; Agent Resources Ninja reinstall).
- Plugin created from your own skills ("Plugin Hunter"): missing for Copilot (SkillJetty `DavidFarris.skill-builder`, 230 installs, builds Claude plugin bundles, not Copilot). [SkillJetty](https://marketplace.visualstudio.com/items?itemName=DavidFarris.skill-builder)
- Diagram of how an element connects to a session: partial (ForgeOne Flow workspace map, Copilot Workspace Manager orchestration graph, Agent Lens session DAG, stale).
- CLI: partial (AI Primitives Hub CLI, ForgeOne Flow CLI, agnix).
- @mentions: Copilot MCP registers an `@mcp` chat participant; Creel (`michael-obele.creel`, 4 installs) attaches skills via `#` references. [Creel](https://marketplace.visualstudio.com/items?itemName=michael-obele.creel)

### Inferences
- The Copilot side has more extensions than the Claude side but no "harness engineering" product: the market is installers and linters. A Copilot port of Claude Harness would enter a space where the best-rated manager has under 100 installs and the only large player (Copilot MCP, ~112k) covers MCP and skills only.
- The biggest threat is first-party: VS Code's built-in Agent Customizations editor plus GitHub's Copilot Evals preview ("inspect GitHub Copilot customizations ... from one VS Code pane") cover the "one place" view, so a third-party product would need to win on the lean-harness checks and the global-vs-repo consolidation that none of them advertise.

### Gaps
- Install counts under ~100 make adoption comparisons noisy; I found no reviews, blog posts or benchmarks comparing these extensions.
- Feature claims were not verified by running the extensions.
