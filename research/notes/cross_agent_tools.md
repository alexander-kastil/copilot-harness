# Cross-agent harness tools that include GitHub Copilot (state 2026-11-04)

Method note: install counts, versions and dates for VS Code extensions come from the VS Code Marketplace gallery API (queried 2026-11-04) and are cited to each listing page; npm weekly downloads come from api.npmjs.org (week 2026-10-27 to 2026-11-02); GitHub stars, last push and last release come from the GitHub REST API (queried 2026-11-04). Feature claims come from each project's own README or Marketplace page, i.e. self-description, not hands-on testing. "Stale" = no release since before 2026-05-04.

Reference point: Claude Harness (`integrations-at.claude-harness`) itself shows 52 installs, v1.0.1 of 2026-11-01, first released 2026-10-12 — [Marketplace](https://marketplace.visualstudio.com/items?itemName=integrations-at.claude-harness).

## Which cross-agent tools exist, and what do they do for Copilot?

### Takeaway
The cross-agent field is large but splits cleanly into five kinds: (1) CLI generators/syncers of the customization layer (rulesync, ruler, APM, ai-rules), (2) skill installers (npx skills and many VS Code skill marketplaces), (3) config linters/visualizers (agnix, Harness Dashboard, Harness Lens, rule-lens extensions), (4) session-history capture/browsers (SpecStory, Chat Wizard), and (5) usage/cost trackers (tokscale, ccusage, waterplane). The high-adoption tools are CLIs without a VS Code UI (rulesync 323k npm/week, skills 5.5M npm/week, APM 4.2k stars); every VS Code extension that covers Copilot plus another agent has small adoption except SpecStory (25k Marketplace + 99k Open VSX) and the MCP/skills installer Copilot MCP (112k).

### Inferences
- Adoption is concentrated in CLIs (skills, rulesync, ruler, APM, tokscale, ccusage); none of them has a VS Code UI. Among cross-agent VS Code extensions only SpecStory (history) and Copilot MCP (MCP/skills installer) pass 25k installs; all "harness"-named extensions are under ~125 installs.
- Copilot customization kinds are covered best by generators: rulesync and APM both handle instructions, prompts/commands, custom agents, skills, hooks, MCP (APM also plugins); ruler stops at AGENTS.md rules, MCP, skills, agents.
- Session-side Copilot coverage exists in three different places with no single tool doing both stores well: VS Code Copilot Chat (`workspaceStorage/.../chatSessions`, read by Chat Wizard, waterplane, SpecStory) and Copilot CLI (`~/.copilot/session-state`, `session-store.db`, OTEL; read by tokscale and Knworks).

- Open VSX counts were checked only for SpecStory, Chat Wizard and a rulesync-named extension.

## Does any cross-agent tool match Claude Harness's depth for Copilot?

### Takeaway
No. Every cross-agent tool covers one or two of the three pillars (one-place editor, session analytics, lean-harness checks), never all three, and in each the Copilot side is thinner than the Claude Code side. The closest partial matches are waterplane (session cost + per-request instruction cost for Copilot, but 4 installs and Claude-first), agnix (lint across Copilot file kinds, but 35 Copilot rules vs 170 Claude), and APM/rulesync (full Copilot primitive coverage, but generation/install only, no UI, no session data).

### Cited Findings
- Pillar "one-place editor": no cross-agent extension offers a single tree to edit Copilot instructions, prompts, agents, skills, hooks, MCP and plugins globally and per repo; the nearest are skill-centric (Agent Skills Ninja: skills plus regenerated instruction index) or visual maps (Harness Dashboard: Copilot adapter reads only `.github/copilot-instructions.md`) — [Agent Skills Ninja README](https://github.com/aktsmm/vscode-agent-skill-ninja); [Harness Dashboard README](https://github.com/marcmassa/harness-manager)
- The only one-place Copilot editor with sessions (Copilot Workspace Manager) is Copilot-only, 52 installs, and reads Copilot CLI sessions as history, not analytics — [GitHub README](https://github.com/Knworks/copilot-workspace-manager)
- Pillar "session analytics": Chat Wizard gives per-model usage analytics and timelines across Copilot and Claude Code, but token counts are approximations and there is no subagent timeline, delegation map or customization-usage view — [Chat Wizard README](https://github.com/veverke/chatwizard)
- waterplane has subagent lanes, context-over-time and a health score for Claude Code; for Copilot it shows premium requests and Chat token use plus the per-request cost of Copilot instruction files — [Marketplace](https://marketplace.visualstudio.com/items?itemName=waterplane-dev.waterplane)
- Pillar "lean-harness checks": agnix lints and auto-fixes Copilot files (`.instructions.md`, agents, prompts, hooks, skills, plugin.json) but its rule depth is 35 for Copilot vs 170 for Claude Code — [agnix README](https://github.com/agent-sh/agnix)
- Duplicate/drift detection exists only as CI drift checks for generated instruction files (agentsync, agentscribe) or rulesync/APM regeneration; none detects oversized skills, duplicate copies across global/repo, or used vs never-used customizations from session data — [agentsync](https://pypi.org/project/mujin-agentsync/); [agentscribe](https://pypi.org/project/agentscribe/); [rulesync](https://github.com/dyoshikawa/rulesync); [APM](https://github.com/microsoft/apm)
- Plugin/version management for Copilot: APM authors and installs Copilot/Claude/Cursor plugins from marketplaces with a lockfile; rulesync supports plugin packaging targets mainly for Claude Code and others (not Copilot) — [APM README](https://github.com/microsoft/apm); [rulesync README](https://github.com/dyoshikawa/rulesync)

### Inferences
- Claude Harness's combination (edit tree + session/subagent/delegation analytics + lean checks + plugin sync/proposal) has no cross-agent equivalent for Copilot; the market gap is real, but rulesync/APM (generation) and Chat Wizard/waterplane (sessions) show the data and formats are reachable.
- "Used vs never-used customizations" for Copilot is absent everywhere found; it would need joining Copilot Chat/CLI session logs with the customization inventory, which no tool does.

### Gaps
- Could not verify whether waterplane's Copilot side covers Copilot CLI or only VS Code Copilot Chat beyond its listing text.
- No benchmarks of accuracy for any tracker's Copilot token figures.

## Is any project announced or in progress to be "a harness manager for Copilot"?

### Takeaway
Several small projects use the "harness" label and include Copilot (Harness Dashboard, Harness Manager by AdmiralGallade, Harness Lens), but each is early-stage (<125 installs, ≤1 star where visible) and Copilot is one adapter among many. No announced, funded or first-party effort to build a Copilot harness manager in the Claude Harness sense was found; APM (Microsoft) is the closest strategic project but is a package manager, not an editor/observer.

### Cited Findings
- Harness Dashboard: renamed from "Harness Manager" at v0.1.0 (2026-06-08); Copilot is an adapter tracked as FEAT-015 detecting `.github/copilot-instructions.md` — [GitHub README](https://github.com/marcmassa/harness-manager); [Marketplace](https://marketplace.visualstudio.com/items?itemName=marcmassacapo.harness-dashboard-vscode)
- Harness Manager (AdmiralGallade) defines a harness as "a collection of files (prompts, rules, hooks, skills)" and writes instruction pointers for Copilot and 9 other tools — [Marketplace](https://marketplace.visualstudio.com/items?itemName=AdmiralGallade.harness-manager)
- Harness Lens describes itself as "an early VS Code integration" built on a language server, covering Copilot instructions and `.agent.md` files — [Marketplace](https://marketplace.visualstudio.com/items?itemName=harness-lens.harness-lens)
- APM targets Copilot first in its README ("Zero-config Copilot", "APM dogfoods this target") and adds governance for orgs — [GitHub README](https://github.com/microsoft/apm)
- Naming collision to avoid: Microsoft's "GitHub Copilot harness" in Copilot Studio (Aug 2026) is an agent runtime option, not a customization manager — [Microsoft Copilot blog](https://www.microsoft.com/en-us/copilot/blog/copilot-studio/new-and-improved-github-copilot-harness-agent-skills-and-richer-context/)
- Wize Development Kit v0.22.0 (2026-09-25) added a Copilot target generating skill and custom agent files — [GitHub release](https://github.com/qwize-br/wize-development-kit/releases/tag/v0.22.0)

### Inferences
- The "harness" term is becoming common for agent-config bundles; Claude Harness competes on depth, not on the name, and the Copilot-capable harness extensions are generators/visualizers without session analytics.

### Gaps
- No roadmap statements from rulesync, ruler or APM about a VS Code UI or session analytics were found.
- GitHub's own roadmap for a first-party customization manager is out of scope here (covered by other researchers).
