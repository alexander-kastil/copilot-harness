# Third-party VS Code extensions and companion tools that analyze GitHub Copilot sessions (state 2026-11-04)

Method note: install counts, ratings and last-update dates come from the VS Code Marketplace gallery API (extensionquery, queried 2026-11-04) and the Open VSX search API; repo stars and last push come from the GitHub REST API on the same day. Feature claims come from each extension's Marketplace README (pulled through the same API) or its GitHub README. "Stale" = no Marketplace update since 2026-05-04 (6+ months). First-party built-ins (Chat Debug view, agent sessions view, GitHub usage dashboards) are out of scope and only named in passing.

## 1. Where Copilot stores session data locally, and what it contains

### Takeaway
There are three local VS Code sources (chatSessions JSONL, the Copilot Chat debug logs, and an opt-in OpenTelemetry SQLite trace DB) plus one Copilot CLI source (`~/.copilot/session-state/<id>/events.jsonl`). Tokens, AI credits, tool calls and subagent runs are recorded in at least one of them; no source I found records hook executions, and the cloud Copilot coding agent leaves nothing local. Third-party authors disagree about how complete the chatSessions numbers are.

### Cited Findings
**VS Code Copilot Chat**
- Chat sessions are stored as JSON logs under `<user data>/User/workspaceStorage/*/chatSessions/*.jsonl`; "since usage-based billing, each turn records `copilotCredits`, `promptTokens`, `completionTokens`". [Happy AI README](https://marketplace.visualstudio.com/items?itemName=happymates.happy-ai)
- Tokenyst reads "the real token" counts from `/workspaceStorage/<hash>/chatSessions/`. [Tokenyst README](https://marketplace.visualstudio.com/items?itemName=TokenystCopilot.tokenyst-copilot)
- AI Insights lists `workspaceStorage/*/chatSessions/` (VS Code, Cursor, VSCodium, Insiders) as its Copilot source with "Actual counts when available, else estimated". [AI Insights README](https://marketplace.visualstudio.com/items?itemName=thewalking-dev.ai-insights)
- Conflict: GitHub Copilot Insights Dashboard states that "sessions in the VS Code Chat panel do not record credits locally, so they are not counted"; it counts only the credits Copilot CLI and agent sessions write to `~/.copilot/session-state/*/events.jsonl`. [GHCP Insights Dashboard README](https://marketplace.visualstudio.com/items?itemName=ShubhJ.ghcp-dashboard)
- Conflict: Token Pie measured one agent-mode workload as 13.5631 credits in the OTel trace DB `agent-traces.db`, 13.6000 by quota delta (ground truth) and only 6.1461 in `chatSessions.copilotCredits`, "a ~55% shortfall on agent-mode work. Trackers built on the session files inherit it." [Token Pie README](https://marketplace.visualstudio.com/items?itemName=token-pie.token-pie)
- Debug logs live at `workspaceStorage/<hash>/GitHub.copilot-chat/debug-logs/<sid>/main.jsonl` with sidecar `system_prompt_*.json`, `tools_*.json`, `models.json`; per-call attributes include `inputTokens`, `cachedTokens`, `outputTokens`, `copilotUsageNanoAiu`, `systemPromptFile`, `toolsFile`. [LedgerLM README](https://github.com/tatsat3mutee/ledgerlm)
- Debug logging must be switched on; Copilot Cost Analyzer says "Enabling debug logging upgrades future sessions to Full", and Copilot Usage Insights Tracker "requires enabling Copilot agent debug logging first". [Copilot Cost Analyzer README](https://marketplace.visualstudio.com/items?itemName=SathvikCheela.copilot-cost-analyzer); [Copilot Usage Insights Tracker listing](https://marketplace.visualstudio.com/items?itemName=Huggiv.copilot-usage-insights-tracker)
- Subagent model calls are logged in separate `runSubagent-*.jsonl` files. [Copilot Cost Tracker README](https://marketplace.visualstudio.com/items?itemName=Hoxlegion.copilot-cost-tracker)
- Conflict on cache tokens: Copilot Tokens lists as a limitation that cached tokens are not recorded because VS Code does not write cache read/write tokens to the log ([Copilot Tokens listing](https://marketplace.visualstudio.com/items?itemName=yuyuanjingxuan.copilot-tokens)); LedgerLM reads a `cachedTokens` attribute from the same debug logs ([LedgerLM README](https://github.com/tatsat3mutee/ledgerlm)). Likely a version difference; not resolved.
- OpenTelemetry: setting `github.copilot.chat.otel.dbSpanExporter.enabled` "populates the data" that Copilot Live Cost & Token Tracker reads (needs Node 24 for the native SQLite binding). [Copilot Live Cost & Token Tracker README](https://marketplace.visualstudio.com/items?itemName=ervi.copilot-live-cost-tracker)
- Privacy warning: "Out of the box, the trace database stores your prompts, Copilot's responses, system prompts, and tool-call results in plain text"; `github.copilot.chat.otel.captureContent=false` "does not stop it". Agents window and Copilot CLI spend "appear not to be recorded" in it. [Token Pie README](https://marketplace.visualstudio.com/items?itemName=token-pie.token-pie)
- VS Code's OpenTelemetry exporter can also be pointed at an exported SQLite DB for per-session and daily token/cost reports. [ypyl/vs-code-copilot-stats](https://github.com/ypyl/vs-code-copilot-stats)
- Session Trace (by digitarald) explores chatSessions `.jsonl` files "and compare[s] with sessionTrace API". [Session Trace listing](https://marketplace.visualstudio.com/items?itemName=digitarald.vscode-session-trace)
- Copilot also stores memories and saved plans locally, which Copilot Usage Studio browses. [Copilot Usage Studio README](https://marketplace.visualstudio.com/items?itemName=fortunes-guardian.copilot-usage-studio-vscode)

**Copilot CLI**
- Each session lives in `~/.copilot/session-state/<session-id>/` with `workspace.yaml` (cwd, git root, branch), `events.jsonl` ("every user message and tool call") and `rewind-snapshots/` (pre-prompt file backups used for exact diffs and revert). [CLI Timeline README](https://marketplace.visualstudio.com/items?itemName=ayushagg31.cli-timeline)
- `events.jsonl` lines carry `type`, `data`, `id`, `timestamp`, optional `parentId`; documented types include `session.start`, `user.message`, `assistant.turn_start`/`turn_end`, `assistant.message`, `tool.execution_start`/`complete`, `subagent.started`/`completed` ("Fleet/background agent spawned"), `skill.invoked`, `session.compaction_start`/`complete`, `session.model_change`, `session.mode_changed`, `session.plan_changed`, `session.task_complete`, `session.shutdown`. [RockNoggin gist: events.jsonl reference](https://gist.github.com/RockNoggin/8cc87f640ce5e3d284298a6db21f7523)
- Usage lives in `session.shutdown` and usage-checkpoint events; shutdown usage is cumulative per session/model pair and resumed sessions emit another snapshot. The CLI can also write OTel JSONL to `~/.copilot/otel/**/*.jsonl` or `COPILOT_OTEL_FILE_EXPORTER_PATH`. [ccusage Copilot CLI guide](https://ccusage.com/guide/copilot/)
- "Shutdown events are not cumulative", so totals need care (contrasting statement from another parser). [microsasa/cli-tools issue](https://github.com/microsasa/cli-tools/issues/2)
- Copilot CLI and agent sessions record AI credits in `events.jsonl`. [GHCP Insights Dashboard README](https://marketplace.visualstudio.com/items?itemName=ShubhJ.ghcp-dashboard)
- Older CLIs log only totals; for CLI usage "latency and tool calls are not logged, so the Turn Explorer uses Copilot Chat data only". [Copilot Cost Tracker README](https://marketplace.visualstudio.com/items?itemName=Hoxlegion.copilot-cost-tracker)
- A `session-store.db` exists next to the session-state folders (read by Copilot Runway). [Copilot Runway via awesome.ecosyste.ms](https://awesome.ecosyste.ms/projects/github.com%2Fjamesmcroft%2Fcopilot-runway)
- Copilot prunes logs after about 14 days; GridWatch snapshots token figures into `gridwatch.json` to survive it. [GridWatch README](https://github.com/abuxton/gridwatch)
- Custom agents live in `~/.copilot/agents/`, skills in `~/.copilot/skills/`. [GridWatch README](https://github.com/abuxton/gridwatch)

**Copilot coding agent (cloud)**
- A search for third-party tools that pull coding-agent session logs or token usage found none; all hits cover local VS Code logs or the CLI. [copilot-session-usage on PyPI](https://pypi.org/project/copilot-session-usage/0.9.1/)

### Inferences
- Per-subagent and per-tool data exist in both VS Code debug logs and CLI `events.jsonl`, so a Claude-Harness-style delegation map is technically buildable for Copilot; nobody has built the full one.
- Because chatSessions under-counts agent-mode credits (Token Pie) and debug logging/OTel are opt-in, any Copilot "session page" needs a setup step that Claude Code transcripts do not require.

### Gaps
- No source documents hook-execution events in chatSessions, debug logs or `events.jsonl`; the gist's event list has none. Whether Copilot hooks are logged at all is unverified.
- No official schema reference for chatSessions JSONL or debug-log JSONL was found in third-party material (first-party docs are another researcher's scope).

## 2. Inventory: which extensions read that data, with quality signals

### Takeaway
The Marketplace holds well over 100 third-party Copilot usage, cost, quota and history extensions, almost all launched in 2025-2026 and most under 1,000 installs. Only five pass 7,000 installs: SpecStory and agsoft's Assist (history), AI Engineering Fluency (token tracker), and Copilot Insights and GitHub Copilot Usage Tracker (quota meters). The richest per-turn analytics sit in small extensions with a few hundred installs.

### Inferences
- Quality pattern: highest-install tools are either history (SpecStory, agsoft) or plan-level meters (Copilot Insights, TMRomain); deep session analytics tools have 10 to 900 installs, 0 to 7 stars and one or two maintainers, so they are young and fragile.
- AI Engineering Fluency is the most established Copilot-specific tracker (16k installs, 123 stars, updated the day before this research) but measures usage habits and tokens, not per-session agent flow.
- The ecosystem is converging on OTel and debug logs as the accurate sources because chatSessions under-reports agent-mode credits.

### Gaps
- Marketplace installs count installs, not active users; no uninstall or active-user figures are available.
- Several extensions have no public repo (netcomlabs, Happy AI, Agent Snitch, sabiku); code quality could not be assessed.
- I did not install or run any extension (brief: install nothing), so all feature claims are README claims.

## 3. Does any tool show which instructions, prompt files, custom agents, skills, hooks or MCP tools were used vs never used?

### Takeaway
No. A handful show partial "used" evidence for some customization kinds, none lists what exists on disk and never fired across sessions. The closest is Copilot Usage Studio's conservative "Customizations Preview" (VS Code only, 39 installs).

### Cited Findings
- Copilot Usage Studio asks "Did my instructions, skills, prompts, hooks, or agents appear in visible Copilot request logs?" and offers a Customizations Preview that "can show when customization text appears in visible VS Code request logs, but it does not claim official billing truth or prove every internal Copilot decision." Copilot CLI is not supported. 39 installs, updated 2026-07-16, [repo](https://github.com/fortunes-guardian/copilot-usage-studio) 5 stars. [Copilot Usage Studio README](https://marketplace.visualstudio.com/items?itemName=fortunes-guardian.copilot-usage-studio-vscode)
- waterplane shows "what your CLAUDE.md, AGENTS.md and Copilot instructions cost every request", modelling load rules (`applyTo: "**"`, matching file touched, by description; skills in `.github/skills` and `.agents/skills` for Copilot), but sessions, costs and context window are Claude Code only; Copilot CLI is not seen. 4 installs, updated 2026-11-02. [waterplane README](https://marketplace.visualstudio.com/items?itemName=waterplane-dev.waterplane)
- LedgerLM's Agents & Tools tab lists which subagents ran (how often, across how many sessions), per-tool call counts, errors and average time, and "skill invocations and hook executions with timing". [LedgerLM README](https://github.com/tatsat3mutee/ledgerlm)
- GridWatch's Agents panel shows built-in and custom agents (`~/.copilot/agents/`) with "session counts, usage stats, and linked session history per agent"; its MCP dashboard lists installed servers and tool catalogues for enabling/disabling, not usage. Copilot CLI only. [GridWatch README](https://github.com/abuxton/gridwatch)
- AI Engineering Fluency's Usage Analysis Dashboard covers "modes, tool calls, context references, MCP tools". [AI Engineering Fluency README](https://marketplace.visualstudio.com/items?itemName=RobBos.ai-engineering-fluency)
- GitHub Copilot Insights Dashboard groups sessions by type including "Custom Agents" and shows MCP server connections. [GHCP Insights Dashboard README](https://marketplace.visualstudio.com/items?itemName=ShubhJ.ghcp-dashboard)
- AI Cost Coach lists "unused habits": "`/compact` never used in a long session, no project instructions file, a token logger that is not recording". [AI Cost Coach README](https://marketplace.visualstudio.com/items?itemName=techselva.ai-cost-coach)
- Happy AI recommends "Deselect unused MCP servers / tool sets for this chat" when tool schemas take a large share of each round. [Happy AI README](https://marketplace.visualstudio.com/items?itemName=happymates.happy-ai)

### Inferences
- The raw signals for a Copilot "find what never runs" view exist (`skill.invoked`, `subagent.*`, `tool.execution_*` in CLI events; `systemPromptFile`/`toolsFile` sidecars and runSubagent logs in VS Code debug logs), but no tool joins them with an on-disk inventory of `.github/instructions`, `.prompt.md`, `.agent.md`, skills, hooks and MCP config.
- Hooks are the weakest link: with no documented hook events in Copilot's local logs, "which hooks fired" is not answerable by any current tool for Copilot.

### Gaps
- Whether LedgerLM's skill/hook analytics is populated for Copilot sources or only for Claude Code could not be confirmed from the README (its Copilot source row lists debug logs only).

## 4. Which tool comes closest to Claude Harness's session page, and what is missing

### Takeaway
Nothing matches Claude Harness for Copilot. Per-session analytics: Copilot Cost Tracker (Hoxlegion) comes closest, followed by Copilot Live Cost & Token Tracker (ervi) and Copilot Cost Analyzer. Delegation display: Copilot CLI Chat's Sub-Agent Dock. Checkpoints: CLI Timeline (stale) and agsoft's per-turn diff/undo. Each covers one slice; no tool draws a delegation map, hook events, failure findings, concurrency, or a never-used inventory.

### Cited Findings
- Copilot Cost Tracker: Turn Explorer "with per-turn LLM/tool calls and cache %", "Only anomalies" filter (cache hit < 40% or turn used tools), per-model cost "accurate across multi-model sessions", budget gauge with pacing, forecast and timeline, All/Chat/CLI switch, subagent model calls supported. 896 installs, 4.25 (4), updated 2026-10-13. [README](https://marketplace.visualstudio.com/items?itemName=Hoxlegion.copilot-cost-tracker)
- Copilot Live Cost & Token Tracker: per prompt "model calls, tool calls (arguments, results, errors), and subagent activity, each with its own token and cost contribution"; one click from status bar to session. 147 installs. [README](https://marketplace.visualstudio.com/items?itemName=ervi.copilot-live-cost-tracker)
- Copilot Cost Analyzer: per-session Timeline "turn-by-turn view of LLM calls and tool calls with token deltas", with subagent boundary and model-switch markers. 243 installs. [README](https://marketplace.visualstudio.com/items?itemName=SathvikCheela.copilot-cost-analyzer)
- Copilot CLI Chat: Sub-Agent Dock lanes per sub-agent with model, tool calls, tokens, duration receipts. 3,965 installs. [README](https://github.com/darthmolen/vscode-extension-copilot-cli)
- CLI Timeline: per-prompt diffs and file revert from Copilot CLI `rewind-snapshots/`. Stale since 2026-03-16. [README](https://marketplace.visualstudio.com/items?itemName=ayushagg31.cli-timeline)
- Claude Code and Codex Assist: per-turn files touched with diff, undo, reapply; File Timeline across sessions; covers Copilot CLI and VS Code chat. 11,797 installs. [README](https://marketplace.visualstudio.com/items?itemName=agsoft.claude-history-viewer)
- Agent Snitch: interactive graph of CLI agent sessions incl. Copilot CLI, but stale and without token data. [README](https://marketplace.visualstudio.com/items?itemName=apoqgin.agent-snitch)
- LLM Log Viewer's subagent tree is Claude Code only. [README](https://marketplace.visualstudio.com/items?itemName=marianoit.llm-log-viewer)
- Plan-limit display: Copilot meters AI credits (`copilotUsageNanoAiu`, $0.01/credit per LedgerLM); status-bar meters such as Copilot Insights, Copilot Pace and Copilot Credit Tracker show monthly allowance and pacing. [LedgerLM README](https://github.com/tatsat3mutee/ledgerlm); [Copilot Insights](https://marketplace.visualstudio.com/items?itemName=emanuelebartolesi.vscode-copilot-insights); [Copilot Pace](https://marketplace.visualstudio.com/items?itemName=RubenBlancoManzano.copilot-pace)

### Inferences
- A Copilot port of Claude Harness would face little direct competition on the agent-flow views (delegation map, findings, concurrency, never-used inventory); the competition is crowded only on cost and quota meters.
- The data problem is real: VS Code chat needs debug logging or OTel switched on for per-call accuracy, and Copilot CLI tool-call detail varies by CLI version, so a Copilot harness would need a setup check that tells the user which source is active.

### Gaps
- No tool claims Copilot coding agent (cloud) analytics; I found no third-party source on getting its per-session token data locally.
- No independent comparison, review article or community thread ranking these trackers was found; the quality assessment rests on installs, ratings, update recency and stars only.
