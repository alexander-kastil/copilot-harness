# VS Code and GitHub Copilot Chat built-ins: how much of a "Copilot harness" view already ships

Scope: what VS Code itself and the GitHub Copilot Chat extension ship today (VS Code 1.146, November 2026) that overlaps Claude Harness (integrations-at.claude-harness). Primary sources are the VS Code docs and release notes, read from the microsoft/vscode-docs repository (main branch, docs dated 11/4/2026). VS Code ships weekly since 1.111 (March 9, 2026), so version numbers are given with release dates.

## 1. Does VS Code or Copilot Chat have its own view or editor that lists and edits the Copilot harness, globally and per repository?

### Takeaway
Yes. Since VS Code 1.113 (March 25, 2026) the built-in **Agent Customizations editor** (Preview; first called "Chat Customizations editor") lists, creates and edits agents, skills, instructions, prompt files, hooks, MCP servers, plugins, tool sets and canvases in User and Workspace scope, per selected agent harness (Copilot, Local, Claude, Codex), with forms, an inline validated editor, a marketplace Browse page, enable/disable per workspace and a Migrations page. It is the open workspace only: there is no multi-repository view.

### Cited Findings
- The Agent Customizations editor "provides a central place to discover, create, and manage customizations for the selected harness", organized into sections "with configuration forms, inline file editors, or read-only details depending on the type and source"; opened with **Chat: Open Customizations** or from the Chat view title bar, and from a **Customizations** entry in the Agents window sidebar ([VS Code docs: Customize agents](https://code.visualstudio.com/docs/agent-customization/overview); source file [overview.md](https://github.com/microsoft/vscode-docs/blob/main/docs/agent-customization/overview.md)).
- Scopes: **User** (across workspaces, not committed), **Workspace** (shared through source control), **Organization** (configured through GitHub, not in the editor). Create a file with the `+` next to Workspace or User; edit in an inline editor "which provides syntax highlighting and validation"; read-only items (for example plugin-provided) offer "open the source file"; plugin-provided customizations are managed from the **Plugins** section ([overview](https://code.visualstudio.com/docs/agent-customization/overview)).
- Introduced in 1.113 (March 25, 2026) as "Chat Customizations editor (Preview)": "a centralized UI for creating and managing all your chat customizations in one place ... tabs, such as custom instructions, prompt files, custom agents, and agent skills ... embedded code editor with syntax highlighting and validation"; MCP servers and agent plugins are added by browsing their marketplace from the editor ([VS Code 1.113 release notes](https://code.visualstudio.com/updates/v1_113)).
- 1.116 (April 15, 2026) added a welcome page with an overview of all customizations and a **Customize Your Agent** input that drafts agents, skills and instructions from a natural-language description ([1.116 release notes](https://code.visualstudio.com/updates/v1_116)).
- 1.112 (March 18, 2026): plugins and MCP servers can be enabled or disabled "both globally and per-workspace" without uninstalling, from the Extensions view or **Chat: Open Customizations**; plugins auto-update per `extensions.autoUpdate` ([1.112 release notes](https://code.visualstudio.com/updates/v1_112)).
- 1.141 (October 7, 2026): the **MCP Servers** section shows servers supplied by plugins, extensions and built-in integrations alongside configured ones ([1.141 release notes](https://code.visualstudio.com/updates/v1_141)).
- 1.144 (October 28, 2026): **Browse** becomes the Customizations home page (GitHub Feed plus configured plugin marketplaces, filter `@type:skill`, `@type:mcp`); Copilot connectors (GitHub-managed MCP servers); completions, hovers and validation in Copilot custom agent files for `model`, `tools`, `skills`, hooks and agent-scoped MCP servers; harness-aware defaults for `.agent.md`; deep links such as `vscode://chat-customizations/open?page=agents|skills|instructions|hooks|mcp-servers|tools|migrations`; `/plugin`, `/mcp`, `/skills` slash commands to list, install, update, enable, disable plugins and inspect MCP servers and skills from chat ([1.144 release notes](https://code.visualstudio.com/updates/v1_144)).
- A **Migrations** page appears when "Copilot cannot use one or more customizations in their current location or format"; a Marketplace-installed skill with missing files gets **Repair** ([overview](https://code.visualstudio.com/docs/agent-customization/overview)). 1.129 added an experimental prompt-file-to-skill migration ([1.129 release notes](https://code.visualstudio.com/updates/v1_129)).
- Claude compatibility since 1.109 (January 2026): VS Code reads `CLAUDE.md` (root, `.claude/CLAUDE.md`, `~/.claude/CLAUDE.md`), `.claude/rules`, `.claude/agents`, `.claude/skills` and `~/.claude/skills`, and hooks in `.claude/settings.json` and `~/.claude/settings.json` "so your agents, skills, instructions, and hooks work across both tools without duplication" ([1.109 release notes](https://code.visualstudio.com/updates/v1_109)).
- VS Code supports several agent harnesses: **Copilot** (Copilot SDK in the Agent Host), **Local** (VS Code's built-in harness), **Claude** ("The Anthropic Claude Agent SDK is integrated into VS Code ... Sessions use Claude project configuration"), **Codex**, and a **Cloud** target ([Choose an agent harness](https://code.visualstudio.com/docs/agents/run/agent-harnesses); [source](https://github.com/microsoft/vscode-docs/blob/main/docs/agents/run/agent-harnesses.md)).
- Earlier building blocks: prompt and instructions files (1.100), custom chat modes (1.101) renamed custom agents (1.106), Agent Skills experimental (1.108) and GA (1.109), agent hooks Preview in the Claude Code hook format with eight events (1.109), agent plugins experimental with Claude-style marketplaces such as `anthropics/claude-code` accepted (1.110), Agent Plugins 1.0 standard support (1.133, August 2026) ([1.109](https://code.visualstudio.com/updates/v1_109); [1.110](https://code.visualstudio.com/updates/v1_110); [1.133](https://code.visualstudio.com/updates/v1_133)).
- Monorepos: `chat.useCustomizationsInParentRepositories` (off by default) walks up to the `.git` root to discover customizations ([overview](https://code.visualstudio.com/docs/agent-customization/overview)).
- Separately published extension **Chat Customizations Evaluations** (`ms-vscode.vscode-chat-customizations-evaluations`, 1.118) analyzes skills, custom agents, instructions and prompt files "for ambiguity, contradictions, and overly complex rules" and writes diagnostics to the Problems panel with **Implement Suggestions** ([overview](https://code.visualstudio.com/docs/agent-customization/overview); [1.118 release notes](https://code.visualstudio.com/updates/v1_118)).

### Inferences
- For the Copilot harness, Microsoft already ships the "edit everything in one place" half of Claude Harness, in core, free, with marketplace discovery Claude Harness lacks. Its unit is the open workspace plus the user profile; it has no table of all repositories, no cross-repo bulk edit, no duplicate detection across scopes.
- Because the editor is harness-aware and VS Code has a Claude harness and reads `.claude/` files, VS Code is now a partial Claude Code harness editor too, not only a Copilot one. Whether the editor shows Claude-only kinds (output styles, slash commands in `.claude/commands`, workflows, memory) was not documented in what I read.
- Quality signal: most of it is labelled Preview or Experimental and moves weekly; behaviour differs by harness (prompt files and tool sets only in the Local harness; GitHub Feed not in Local).

### Gaps
- No doc page lists the exact sections of the editor for the Claude harness; the 1.109 compatibility list names only instructions, rules, agents, skills and hooks.
- Not verified whether the editor offers typed frontmatter forms for every kind or only for some (docs say "forms, inline file editors, or read-only details depending on the type").
- Not verified: a search snippet claims the Copilot Chat extension source now lives under `extensions/copilot` in microsoft/vscode; I did not confirm it in a primary source.

## 2. Does either show how a Copilot session ran: tokens or cost, subagents, tool calls, checkpoints and restore, which instructions, agents and skills were used?

### Takeaway
Yes, per session, and in some respects deeper than Claude Harness: the **Agent Debug Logs** panel (Preview since 1.110, February 2026; persisted history since 1.116) has a Logs view grouped by subagent, a Summary (tool calls, tokens, errors, duration), an **Agent Flow Chart** of agents and subagents, a **Cache Explorer**, `/troubleshoot`, and OTLP export; the **Chat Debug view** shows system prompt, context and tool payloads; chat shows session cost, per-subagent AI credits and per-turn tokens per model; **checkpoints** restore files and chat history since 1.103. Missing are cross-session analysis and the multi-view analytics (concurrency, scatter, token flow, findings).

### Cited Findings
- Agent Debug Logs panel: "a chronological record and aggregate metrics for chat sessions", opened via **Show Agent Debug Logs** or **Developer: Open Agent Debug Logs**; "includes current and historical sessions. Persisted logs are stored locally" ([Debug chat interactions](https://code.visualstudio.com/docs/agents/agent-troubleshooting/chat-debug-view); [source](https://github.com/microsoft/vscode-docs/blob/main/docs/agents/agent-troubleshooting/chat-debug-view.md)).
- Logs view: events with timestamp, type, summary; expand for system prompt or tool input and output; "Switch between a flat list and a tree grouped by subagent"; filters for model requests, tool calls, discovery, errors ([chat-debug-view](https://code.visualstudio.com/docs/agents/agent-troubleshooting/chat-debug-view)).
- Summary view: "tool calls, token usage, errors, and total duration"; Agent Flow Chart "visualizes the sequence of interactions between agents and subagents ... identify which agent delegated an action and where a workflow stopped"; Cache Explorer "compares consecutive model requests and marks their first divergence" ([chat-debug-view](https://code.visualstudio.com/docs/agents/agent-troubleshooting/chat-debug-view)).
- Which customizations were used: "Check **Discovery** events in the Agent Debug Logs to see whether a customization was loaded, skipped, or rejected"; `/troubleshoot Which customizations were loaded, and did any fail?`; the response's **References** section is another inclusion check ([chat-debug-view](https://code.visualstudio.com/docs/agents/agent-troubleshooting/chat-debug-view)). The 1.110 notes: "You can see exactly which prompt files, skills, hooks, and other customizations are loaded for a session"; it replaced the 1.109 **Diagnostics** chat action, which listed loaded agents, prompts, instructions and skills with load status and errors ([1.110](https://code.visualstudio.com/updates/v1_110); [1.109](https://code.visualstudio.com/updates/v1_109)).
- Limits: capture must be switched on first ("Capture is not retroactive"; experimental settings `chat.agentHost.agentDebugLog.enabled` or, for Local, `github.copilot.chat.agentDebugLog.fileLogging.enabled`); panel is Preview ([chat-debug-view](https://code.visualstudio.com/docs/agents/agent-troubleshooting/chat-debug-view)). At 1.110 it covered only local sessions and was not persisted ([1.110](https://code.visualstudio.com/updates/v1_110)); 1.113 extended it to Copilot CLI and Claude sessions ([1.113](https://code.visualstudio.com/updates/v1_113)); 1.116 persisted past sessions ([1.116](https://code.visualstudio.com/updates/v1_116)).
- Export and import a session as OpenTelemetry JSON (OTLP) (1.112) ([1.112](https://code.visualstudio.com/updates/v1_112); [chat-debug-view](https://code.visualstudio.com/docs/agents/agent-troubleshooting/chat-debug-view)). OTel tracing (1.119, May 6, 2026) for Local, Copilot CLI and Claude agent sessions: `invoke_agent` root span with `chat`, `execute_tool`, `execute_hook` children, subagents parented to the calling tool span, token usage "including cache read and cache creation breakdowns" ([1.119](https://code.visualstudio.com/updates/v1_119)).
- Chat Debug view: per request System prompt, User prompt, Context, Response, Tool responses ([chat-debug-view](https://code.visualstudio.com/docs/agents/agent-troubleshooting/chat-debug-view)).
- Cost and tokens in chat: context window indicator with token breakdown by category (1.109) ([1.109](https://code.visualstudio.com/updates/v1_109)); "cost for an entire chat session, not just for individual turns" (1.126, June 24, 2026) ([1.126](https://code.visualstudio.com/updates/v1_126)); hover a subagent section "to see the AI credits used by that subagent" (1.127, July 1, 2026) ([1.127](https://code.visualstudio.com/updates/v1_127)); footer hover with "per-model breakdown of the input, cached input, and output tokens used in that chat turn" (1.135, August 26, 2026) ([1.135](https://code.visualstudio.com/updates/v1_135)); percentage of additional Copilot budget used in the status dashboard (1.125) ([1.125](https://code.visualstudio.com/updates/v1_125)). Copilot moved to usage-based billing in 1.122 ([1.122](https://code.visualstudio.com/updates/v1_122)).
- Checkpoints since 1.103 (2025): "VS Code reverts workspace changes and the chat history to that point. After restoring a checkpoint, you can redo" ([1.103](https://code.visualstudio.com/updates/v1_103)). Current docs: **Restore Checkpoint** "restores affected workspace files and chat history" and "removes subsequent conversation turns"; it "doesn't reverse completed terminal commands, network requests, deployments" ([Review code edits](https://github.com/microsoft/vscode-docs/blob/main/docs/agents/run/review-code-edits.md)).
- Session history: Sessions list across Local, Copilot CLI, Claude and Codex sessions, can show external Copilot or Claude sessions created in other apps and continue them (1.135) ([1.135](https://code.visualstudio.com/updates/v1_135)); session sync to the GitHub account and `/chronicle` to query past sessions, generate standups, search by topic, file or PR (1.123, June 3, 2026) ([1.123](https://code.visualstudio.com/updates/v1_123)).
- Microsoft's own experimental **Session timeline** plugin (microsoft/vscode-team-kit, Agent Plugins 1.0 package, needs a Copilot host with SDK canvas extensions) renders the current Copilot session "as a live, searchable timeline canvas" with tool catalogs, nested subagent activity, durations, model names and JSONL export ([session-timeline README](https://github.com/microsoft/vscode-team-kit/tree/main/session-timeline)).
- Organization level: GitHub's Copilot usage metrics dashboard and API (GA February 2026) report agent adoption at enterprise level ([GitHub changelog](https://github.blog/changelog/2026-02-27-copilot-metrics-is-now-generally-available); [docs.github.com](https://docs.github.com/en/copilot/reference/copilot-usage-metrics/copilot-usage-metrics)); one trade article says an October 22, 2026 update names individual skills, custom agents, MCP servers, slash commands and plugins instead of "custom" ([Visual Studio Magazine](https://visualstudiomagazine.com/articles/2026/10/28/github-copilot-usage-metrics-now-identify-custom-skills-agents-and-mcp-servers.aspx)); not confirmed in GitHub docs.

### Inferences
- For one session, VS Code's Summary plus Flow Chart plus Logs covers what Claude Harness's session page does for delegation, tokens and tool calls, and adds raw prompt payloads and a cache-divergence view that Claude Harness does not have.
- Quality differences: VS Code needs logging switched on in advance (Claude Harness reads transcripts the CLI already writes, retroactively); VS Code reports cost in Copilot AI credits, Claude Harness in API list-price dollars per token class; VS Code checkpoint restore is all-or-nothing with turn removal, Claude Harness shows a per-file diff card before restore and offers a separate conversation rewind.

### Gaps
- No source found for a built-in cross-session view: cost per agent type or per model over 7 days, concurrency peak, scatter by run time and tokens, token-flow view, or "findings" such as silent agents or general-purpose runs where a custom agent fits.
- Not established whether the Agent Flow Chart marks hook-denied tool calls the way Claude Harness's delegation map does (OTel has `execute_hook` spans; display not documented).
- The October 2026 per-customization usage metrics rest on one secondary source.

## 3. Which Claude Harness features have no equivalent there?

### Takeaway
Nothing built in matches Claude Harness as a whole. VS Code covers per-workspace editing, marketplace install and update, and per-session debugging well; it has no equivalent for cross-session "what never runs", harness hygiene (duplicates, size, dead pointers), cross-repo overview and bulk operations, Plugin Hunter or Automation Hunter, per-element drawings, Cowork handover, or a harness CLI with `@` mentions.

### Cited Findings
- Covered or partly covered (with source):
  - Edit all kinds globally and per repo: Agent Customizations editor, User and Workspace scope ([overview](https://code.visualstudio.com/docs/agent-customization/overview)).
  - Session cost, subagents, tool calls, flow: Agent Debug Logs, session cost, subagent credits ([chat-debug-view](https://code.visualstudio.com/docs/agents/agent-troubleshooting/chat-debug-view); [1.126](https://code.visualstudio.com/updates/v1_126); [1.127](https://code.visualstudio.com/updates/v1_127)).
  - Checkpoints and restore ([1.103](https://code.visualstudio.com/updates/v1_103)).
  - Effective harness of one session: Discovery events, References ([chat-debug-view](https://code.visualstudio.com/docs/agents/agent-troubleshooting/chat-debug-view)).
  - Keep plugins current: marketplaces, auto-update, `/plugin update`, enable or disable per workspace ([1.112](https://code.visualstudio.com/updates/v1_112); [1.113](https://code.visualstudio.com/updates/v1_113); [1.144](https://code.visualstudio.com/updates/v1_144)).
  - Quality lint of a customization file: Chat Customizations Evaluations extension, separate install ([1.118](https://code.visualstudio.com/updates/v1_118)).
  - Draft customizations with AI: Customize Your Agent ([1.116](https://code.visualstudio.com/updates/v1_116)).
  - Continue sessions from other apps: external Copilot or Claude sessions ([1.135](https://code.visualstudio.com/updates/v1_135)).
- Claude Harness features for comparison, from its README: Used in / Fired in / Loaded in tabs with "never used" presets; skill Size card; consolidate duplicates with retire and merge; CLAUDE.md lenses for dead pointers; GitHub Repo overview of every repository; Plugin Hunter; Automation Hunter; Drawings (Harness and Process view per element); Cowork Handover; marketplace health with "ahead" counts and Sync all; `harness` CLI, `.harness` scripts and `@harness:` mentions; six session views including Concurrency, Scatter and Token flow ([Claude Harness README](https://marketplace.visualstudio.com/items?itemName=integrations-at.claude-harness)).

### Inferences
- No built-in equivalent found for: cross-session usage of each agent, skill, hook, rule or MCP tool with "never used" lists (VS Code is per session; GitHub's org metrics are enterprise dashboards, not in the editor); skill size and context-cost ranking; duplicate detection and retire or merge across user, workspace and plugin scopes (only Migrations and Repair exist); dead-pointer lenses in instruction files; one table of all repositories and bulk-edit guards; building a plugin from existing skills (Plugin Hunter); procedure mining (Automation Hunter); per-element architecture drawings (the Flow Chart is per session only); Concurrency, Scatter and Token-flow views; findings with suggested fixes; a harness CLI and scriptable `.harness` files.
- The closest Microsoft-made session visualizer outside core is the experimental Session timeline plugin; it is live-session only and does not aggregate.
- Net: a "Copilot harness" extension of Claude Harness quality would duplicate much of the editor and single-session debugging that VS Code now ships, so its value would sit in the cross-session, cross-repo and hygiene features listed above.

### Gaps
- Did not inventory third-party Marketplace extensions (other researchers cover them).
- Did not test the features hands-on; all claims are from docs and release notes, and most are Preview or Experimental.
